# Prospective candidate-support test

Status: **proposed; no launch or adoption qualification**. Freeze and hash this protocol, the complete seed selection, incumbent source/assets, identity implementation and evaluation roster before reading new labels. Claude retains run/submission coordination.

## Question and arms

A0 is the exact current eligible incumbent candidate-generation and ranking pipeline. A1 changes only candidate generation: on weak-library queries (the existing observed library threshold 0.90), generate this fixed one-edit supplement from the ten top spectral analogues supplied by the incumbent. The seed stage uses measured spectra only. Do not select the true parent, truth formula, source record ID, known label or best edit after evaluation.

Freeze edit family, budgets and a 10-ppm measured-neutral-mass window; use the incumbent's already registered observed-precursor union where applicable rather than invent a truth-formula filter. Retain every incumbent candidate before final scoring. Identify new candidates by the official metric quotient, then recompute the candidate-relative ranker features in the common universe using the same ranker parameters and eligible weights. This intentionally changes candidate-relative features; do not mistake an unchanged weight file for unchanged incumbent predictions.

Preserve A0 predictions from the same run. Seal A1 additions, metadata and both prediction lists before joining any truth. No RRF, formula cap, second list, popularity change, new ranker training or new model pass belongs to this arm.

## Stage 0: inexpensive diagnostic before ranker integration

Use at least 200 preselected identity groups from an exposure-disjoint role. The roster must exclude optimizer training, validation/checkpoint selection, ranker-query construction, library labels available to the selector and external-model training/selection exposure for every incumbent component. A role number alone is insufficient. If complete exposure manifests cannot establish this, label results exposed development and do not adopt or submit on their strength.

Choose and pin the roster using metadata and deterministic hashed identity strata before outcome access. Do not choose only known candidate misses. Do not use test spectrum IDs, source IDs, manually selected answers or hidden labels as runtime inputs. Compute seeds from the training-only library after removing all held-out structures and all of their spectra. External candidate catalogues may retain structures under the retrieval-task contract, but their presence must be reported separately.

For each query, write and hash:
- measured adduct/charge/multiplicity and neutral-mass provenance;
- seed rank, spectral score and canonical seed identity;
- incumbent canonical candidate identities, generated identities and edit provenance;
- attempted/sanitized/mass-compatible counts, truncation/unsupported flags and wall/CPU time.

Only after sealing, evaluate whether the true official identity is present in A0 and A1. Report candidate support before ranking, new true-identity recoveries, unsupported/multi-edit failures and recall by library-confidence/mass/adduct/instrument strata. Report candidate-outside-A0 strata descriptively after evaluating the full frozen roster; never condition the main effect on their labels.

Stop the arm if any incumbent identity is removed, mass provenance is unknown, an official identity cannot be normalized, actual CPU cost exceeds 120 seconds for the first 200-group screen, or unregistered truncation occurs. Prototype truncation may be a registered budgeted result, but its frequency and retained/omitted support must remain explicit.

A necessary support gate is at least five newly recovered identities among 200 groups, with no incumbent support loss. This is a cost screen, not a score-gain claim. If fewer recoveries occur, stop rather than widening the edit family or seed cap on this panel.

## Stage 1: ranking and score sensitivity

Only after Stage 0 passes, evaluate one sealed A1 ranker integration on the whole exposure-disjoint panel. Report:
1. A0/A1 candidate recall under the exact metric identity;
2. MRR@25 on the full frozen panel, not only new-recovery queries;
3. MRR conditional on incumbent-supported queries to detect decoy displacement;
4. top-1 changes, gains/losses and missing/unsupported/truncated counts.

Use molecule-level paired resampling (5,000 fixed-seed bootstrap replicates). A prospective advance gate is full-panel paired delta MRR@25 at least +0.010 and a 90 percent lower bound above zero, while incumbent-supported MRR loss is no greater than 0.005. Require no material instrument/adduct harm under strata registered before labels; low-count strata remain unresolved, not automatically passing.

Do not loosen these gates after results. An earlier rejected overlay is counter-evidence to broad candidate additions; this arm differs by generating graph neighbours, but it still must earn adoption.
