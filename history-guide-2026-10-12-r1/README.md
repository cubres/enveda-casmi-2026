## Before a fork

Start with the stated input contract, dependency pins and provenance. Reproduce the documented controls first, in a fresh output folder if required. Record your changed source hash and explain which claim your run can test. Preserve failed results and distinguish local controls, native qualification and an exact completed official result.

For a safe first inspection, the shared [Static notebook execution map](https://github.com/cubres/gemma-4-developer-agent/blob/4b21f05ee4542c9f0c5a9dfd2a6d7081385af6d7/tools/notebook-execution-map/2026-10-05/README.md) reads direct configuration assignments without executing or editing notebook code. It cannot see effective settings inside embedded script strings, and it does not estimate quota or runtime.

The GitHub links above pin historical published commits. They describe those dated artifacts; they do not assert the current account status or a new leaderboard gain.
