CASMI candidate data: COCONUT V2 and a small attributed ChEBI example
Evidence checked 2026-10-15; no model evaluation or competition score claimed.

WHAT THIS ADDS

This catalog separates a public candidate bank from its upstream database and
from an independently reproducible chemical-record example. The public COCONUT
bank is useful for bounded mass-window retrieval. The ChEBI example is useful
for testing a candidate-record schema without downloading a large bank or
requiring RDKit, NumPy, credentials, or competition data.

The card describes masses as sorted neutral monoisotopic masses in daltons.
Each row uses 6,930 selected fingerprint bits, packed into 867 bytes with six
padding bits. The selection indexes a 10,407-bit vector made from Morgan
radius 2 (4096), Morgan radius 3 (4096), RDKit path (2048, maxPath 6), and
MACCS (167). Row order must stay identical across mass, fingerprint, and
identity arrays. A precursor m/z is not automatically a neutral mass.

Use the existing version-pinned numeric companion for mass-window lookup:
https://github.com/cubres/enveda-casmi-2026/blob/51d3990f714318d828e199747f412a9421fbcd4e/datasets/coconut-lookup-companion/README.md
It preserves row indices, bounds decoding to 4096 rows, and avoids pickle.
Its invented-data tests do not establish real-bank alignment or chemistry.

The campaign's retained input metadata names this dataset without a version
suffix. Advertised current V2 does not prove which version or absolute mount
path a native job resolved. The V6 serving bank uses a different 10,395-feature
layout: do not substitute this 6,930-feature bank or its bit selector into that
model. This catalog does not change the notebook or its inputs.

RUN THE DEMO

Requires Python 3.9+ standard library only. Run from this packet's directory.
The output directory must be new; existing outputs are never overwritten.

Validate the included exact snapshot, offline:

python3 chebi_candidate_demo.py \
  --input demo_verified_caffeine_once/source.json \
  --expected-sha256 d7d96d4aaac053f52b78b4ddf52fb295d0b54edaaf00fc7510b4ee26c227c753 \
  --output caffeine_offline_check

Retrieve one fresh public record and create its own snapshot:

python3 chebi_candidate_demo.py --chebi-id 27732 --output caffeine_new_snapshot

The downloader makes one GET, rejects redirects, accepts JSON only, caps the
body at 256 KiB, and uses a 20-second socket timeout. It neither authenticates
nor retries. The timeout is not a hard total wall-clock limit. A fresh API
response may legitimately differ; it receives a new hash rather than silently
replacing the included example. --expected-sha256 can require any known exact
snapshot. Output files are source.json, candidate.json, and receipt.json.

The validator deliberately accepts only released, three-star, neutral records
with explicit structures, positive finite decimal masses, standard InChI and
InChIKey syntax. Charged species, generic classes, and incomplete records may
be valid ChEBI entries but fall outside this small demo. Schema acceptance is
not proof of chemical correctness, absence of polymers, normalization policy,
stereochemical equivalence, fingerprint compatibility, or model performance.
There is no competition query, spectrum, label, split, or submission here.

Data flow:
  Official ChEBI HTTPS response -> bounded raw bytes -> SHA-256
       -> explicit schema checks -> selected candidate fields + receipt
  Included exact snapshot ------> same offline checks; no network
